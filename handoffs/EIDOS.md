# Eidos Convergence Handoff

Status: v0.2.1 reconciliation input

## Canonical Role

Eidos is the deterministic Experience and interaction runtime.

Canonical interpretation:

> EC proposes Experience intent. Eidos deterministically validates, constrains and realizes Experience. Humans interact and decide. Host/EVO authorizes and executes business effects.

Eidos validates and realizes Experience proposals using explicit, versioned, discoverable and composable capabilities. It does not own enterprise operational truth or persistent enterprise learning.

## Constitutional Principles to Preserve

- Composition Before Generation
- Capability Before Component
- `LLM proposes. Contracts describe. Validators verify. Runtime realizes.`
- Shared core, personal periphery
- Adaptation should converge toward fit, not produce perpetual change

## Eidos Owns

- Experience public contract validation
- Experience Capability Catalog
- Experience composition/resolution
- Deterministic Experience Runtime and renderer abstraction
- Experience Stability semantics
- Experience Integrity invariants
- Shared Core / Personal Periphery constraints
- Decision Experience semantics
- Attention semantics
- Motion semantics
- Direct Manipulation semantics
- Accessibility constraints
- Renderer-independent interaction state
- Interaction semantics
- Human confirmation semantics
- Host-neutral ActionRequest production
- Deterministic proposal diagnostics / repair surface
- Standard deterministic fallback behavior

## Eidos Does Not Own

- EVO business facts or operational definitions as an alternate source of truth
- EVO authorization or Command execution
- EC knowledge, enterprise memory or long-term learning
- a competing long-term personalization/user-intelligence brain
- arbitrary business mutation outside Host/execution-substrate public boundaries

## EC Boundary

`EC Experience Proposal -> Eidos validation -> deterministic resolution/realization`

EC may propose adaptation/personalization intent. Eidos owns deterministic admissibility, Experience Integrity and realization.

EC cannot instruct Eidos to violate mandatory evidence, accessibility constraints, organization/shared constraints, Decision Integrity, Experience Integrity or Capability Catalog limitations.

## Canonical Action Boundary

The universal Eidos boundary is Host-neutral:

`Human -> Eidos interaction -> ActionRequest -> Host`

An ActionRequest is a deterministic semantic interaction request. It may be mapped by the Host to an authorized enterprise service, local deterministic host behavior, navigation, collaboration action, document operation or another execution substrate.

For the EVO integration profile:

`Human -> Eidos -> ActionRequest -> Host Adapter -> EVO Command -> EVO authorization/validation/execution`

Human confirmation is evidence of an interaction step; it is not final business authorization.

## Cross-Repo Priorities

- Formalize modern Experience Proposal semantics and capability negotiation.
- Keep ActionRequest host-neutral while defining a certified EVO mapping profile.
- Preserve experience-instance, capability-version, correlation/causation and presentation-state evidence through the action path.
- Define deterministic diagnostics/fallback for unsupported proposals/capabilities.
- Keep query/action boundaries separate from Eidos renderer internals.
