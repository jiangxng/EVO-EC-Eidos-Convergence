# Experience Compiler (EC) Convergence Handoff

Status: v0.2.1 reconciliation input

## Canonical Role

EC is the persistent enterprise intelligence system: it knows, remembers, learns, researches, reasons, diagnoses, recommends and improves how it learns.

LLMs are replaceable reasoning engines; EC is the persistent intelligence substrate.

## EC Owns

- Knowledge/provenance and evidence
- Enterprise/industry memory
- Cases, decisions, outcomes, lessons, patterns
- Learning and learning methods
- Research
- Context compilation
- Reasoning, diagnosis, recommendation
- Management Intelligence
- SOP / Metric / Flow / Capability Intelligence
- Scenario/hypothesis design and simulation interpretation
- Enterprise Intelligence Packs
- Enterprise Function Packs
- Knowledge Merge
- Experience Proposal production
- Command Proposal and Operational Change Proposal production

## Required EVO Boundaries

- Enterprise Context for governed current/versioned operational understanding.
- Enterprise Observation for facts/outcomes/changes used by the learning loop.
- Command Proposal admission into the normal EVO Command path.
- Operational Change Proposal governance for learned improvements.
- Enterprise Simulation for deterministic consequence calculation.

## Required Eidos Boundary

EC produces high-level, versioned Experience Proposals. Eidos validates and deterministically realizes them. EC does not generate arbitrary executable Eidos runtime code as the normal boundary.

## Learning Invariant

EC learning output is not operational truth.

`Learning -> Recommendation/Proposal -> Validation -> Authorization/Governance -> Published Version/Command -> EVO execution`

EC must preserve provenance, scope, time/version and uncertainty/contradiction state when learning from operational observations.
