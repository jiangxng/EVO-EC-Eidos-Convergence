# Cross-Repository Ownership Manifest v0.2

Status: Proposed for Architecture Convergence v0.2.1

## Canonical Boundary

> EC thinks, learns and improves. EVO executes. Eidos deterministically realizes and governs human-system Experience and interaction semantics.

Convergence governs cross-system semantics only. Each product Constitution remains authoritative over that product's internal architecture unless an explicit CRCP/ADR changes it.

## EVO Ownership

EVO owns deterministic operational truth and execution:

- Business facts / BusinessData
- Command admission, authorization, validation and execution
- Effective operational definitions
- Operational Capability definitions
- Published SOP Runtime definitions
- Flow definitions, instances, traces and lineage
- Metric definitions, deterministic calculation, values, history and lineage
- Ledger, balances, cost, valuation and deterministic runtime state
- Deterministic replay
- Deterministic enterprise consequence/simulation engines
- Governed enterprise queries
- Authoritative operational observations and outcome projections derived from EVO operational truth

EVO does not own long-term enterprise learning, management intelligence, persistent reasoning, experience planning or personalization intelligence. EVO operational outcome facts/projections are distinct from EC outcome interpretation.

## EC Ownership

EC owns persistent enterprise intelligence:

- Knowledge and provenance
- Enterprise and industry memory
- Cases, decisions, outcomes, lessons and patterns
- Learning and learning methods
- Research and evidence acquisition
- Reasoning, diagnosis and recommendation
- Scenario/hypothesis design and interpretation
- Context compilation
- SOP / Metric / Flow / Capability Intelligence
- Management Intelligence
- Enterprise Intelligence Packs
- Enterprise Function Packs
- Knowledge Merge
- Long-term user/enterprise understanding where governed
- Experience-intent proposal generation for Eidos
- Command Proposal generation for EVO
- Operational Change Proposal generation: rationale, evidence, recommendation and change intent

EC does not own EVO authorization, EVO Command semantics, EVO definition mutation language, EVO operational truth, or Eidos Experience admissibility. EC must not write EVO or Eidos internal state directly.

## Eidos Ownership

Eidos owns deterministic Experience semantics and realization:

- Experience public contract validation
- Experience Capability Catalog
- Experience composition/resolution
- Deterministic Experience Runtime and renderer abstraction
- Experience Stability semantics
- Experience Integrity invariants
- Shared Core / Personal Periphery constraints
- Decision Experience semantics
- Attention semantics
- Motion semantics
- Direct Manipulation semantics
- Accessibility constraints
- Renderer-independent interaction state
- Interaction semantics
- Human confirmation semantics
- Host-neutral ActionRequest semantics and production
- Deterministic proposal diagnostics / repair surface
- Standard deterministic fallback behavior

Eidos does not own enterprise truth, business authorization/execution, persistent enterprise learning, EC knowledge, or a competing long-term user-intelligence model.

EC may propose adaptation/personalization intent. Eidos owns deterministic admissibility and realization and may reject any proposal that violates mandatory evidence, accessibility, organization/shared constraints, Experience Integrity or Decision Integrity.

## Convergence Workspace Ownership

Convergence owns cross-repository governance artifacts, not product runtime behavior:

- Contract registry and mirrored/certified schemas
- Cross-repository ownership manifest
- Shared vocabulary and reusable semantic profiles
- Compatibility matrix
- CRCP workflow
- Cross-repository ADRs
- Golden fixtures
- Contract and integration tests
- Reference enterprise packs used for convergence testing
- Cross-system deployment/certification guidance

## Contract Ownership

| Contract family | Canonical owner | Principal consumers/producers |
|---|---|---|
| EVO Command | EVO | EC proposals, Host-mapped Eidos actions, automation, humans |
| Enterprise Context | EVO | EC, Eidos/Host as authorized |
| Enterprise Observation | EVO | EC |
| Enterprise Simulation | EVO owns deterministic calculation contract; EC owns scenario reasoning semantics | EC |
| Command Proposal | EC owns recommendation/proposal envelope; EVO owns referenced Command semantics, input schema and admission | EC -> EVO |
| Operational Change Proposal | EC owns proposal-generation, rationale/evidence and change-intent semantics; EVO owns target-definition schema/mutation language, governance, validation, approval enforcement, publication and effective versioning | EC -> EVO |
| Experience Proposal | Eidos owns public validation/admissibility contract; EC owns producer/intelligence intent | EC -> Eidos |
| ActionRequest | Eidos owns host-neutral interaction request contract; Host owns mapping; EVO owns final Command admission for the EVO integration profile | Eidos -> Host -> execution substrate |
| Enterprise Intelligence Pack | EC | EVO/Eidos publishers consume compiled outputs |
| Enterprise Function Pack | EC | EC lifecycle; publishers may consume compiled outputs |
| Knowledge Merge | EC | EC instances |

When a contract spans ownership concerns, the public schema must explicitly separate fields/semantics by owner rather than creating ambiguous shared ownership.
